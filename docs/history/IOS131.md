# Safari held controls and Home Screen mode

Controls explicitly disable -webkit-user-select, user-select, -webkit-touch-callout and WebKit drag on buttons and nested captions, HUD and gameplay chrome. Scoped delegated selectstart/contextmenu/dragstart guards prevent control-label selection and callouts without swallowing touchstart/click activation or disabling native form selects and readable dialog prose. Existing pointer capture and independent input-source releases remain unchanged.

Fullscreen tries standard or prefixed requests/exits. Unsupported/rejected requests open a visible paused help dialog describing Safari Share → Add to Home Screen → Open as Web App → launch icon. Close restores the prior pause state. Real fullscreen changes update Enter/Exit labels; an installed standalone app hides the redundant button. Starting a level only attempts native fullscreen where appropriate and never automatically opens installation help.

Added standalone web manifest and Apple compatibility metadata, preserving safe-area layout. No service worker or offline promise: launches use the current live game. Manifest source is config/web-app-manifest.json and build output app-manifest.json.

Source references: https://webkit.org/blog/17333/webkit-features-in-safari-26-0/ and https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/SafariWebContent/ConfiguringWebApplications/ConfiguringWebApplications.html . iOS26 defaults Home Screen additions to web-app mode; older versions use explicit manifest/Apple metadata. Native fullscreen support is feature-tested rather than inferred from user-agent.

Verification:652 tests passed; release hash check474files. WebKit26.5 on Windows and Chrome mobile contexts pass one-second held movement, nested selection/contextmenu/drag cancellation, release/stopping, untouched prose/native selects, paused fullscreen help, preservation of prior pause, manifest retrieval and standalone detection. Chrome additionally verifies two-finger move+action and releasing action while movement remains held. Explicit native fullscreen button entry/exit passed in Chrome, including Exit/Enter label changes. The automatic level-card attempt may be rejected once its asynchronous load loses user activation; the real fullscreen button succeeds. No physical iPhone was available: OS-level callout and installation UI are covered by the explicit Safari CSS and documented Home Screen path, not claimed as on-device tests.
